# Step 3: Local Sandboxed Evaluation & Proxy Training (Offline Referee)

Welcome to **Step 3**! In this step, we explore the **Referee** of AlphaEvolve: the local evaluation harness.

This step runs **100% locally with ZERO Google Cloud API calls and ZERO cost**.

## 🔒 Why Client-Side Evaluation? (Enterprise PSO Value)

When presenting to enterprise customers, this is one of AlphaEvolve's biggest selling points:

1. **Data Privacy & Compliance (Zero Data Exfiltration):**
   * Proprietary or regulated customer datasets (e.g. healthcare records, banking transactions) **NEVER** get sent to the LLM.
   * Only the *abstract architecture code* is generated by Gemini. The actual compilation and training happen entirely within the customer's secure perimeter (laptop, private GKE cluster, or Vertex Workbench).
2. **Compute Flexibility:**
   * You choose the compute backend: MacBook CPU, an on-prem GPU server, or a Ray cluster.
3. **Cost Control:**
   * You don't pay Gemini to execute code. Gemini only generates text.

---

## ⚡ The Proxy Evaluation Methodology

If an evolutionary tournament tests 50 different neural network designs, training each one for 50 epochs on the full 60,000 MNIST images would take hours.

**The Solution: Proxy Split**
* **Train split:** 10,000 normalized images.
* **Validation split:** 2,000 images.
* **Epochs:** Exactly **2 epochs** with batch size 64.
* **Training time:** Only **~1.5 to 2.0 seconds** per model on standard CPU!
* **Ranking Validity:** Extensive NAS research proves that proxy accuracy has a **> 0.90 Spearman rank correlation** with full-scale convergence. If an architecture is better in proxy, it is almost certainly better after full training!

## 🛡️ Safe Execution Pipeline in `evaluate.py`

Before training begins, `evaluate.py` guards against crashes:

```
Candidate Code (string)
         │
         ▼
 1. exec() in isolated namespace   ──> Catches syntax errors & illegal imports
         │
         ▼
 2. Dummy forward pass (zeros)     ──> Verifies (1, 28, 28, 1) -> (1, 10) shapes
         │
         ▼
 3. Proxy Training (2 epochs)      ──> Measures val_acc, val_loss, param_count
         │
         ▼
 4. Error Catcher                  ──> Converts any OOM or tensor bugs into LLM insights
```

## 🚀 How to Run Step 3

Execute the single runner script:
```bash
./run.sh
```

### What happens when you run `./run.sh`:
1. Loads and caches the normalized MNIST proxy dataset.
2. Compiles `program.py` in an isolated namespace.
3. Performs a dummy shape check.
4. Trains the baseline CNN for 2 fast epochs.
5. Prints the primary metric (`val_accuracy` ~91-94% in proxy), parameter count, and loss.
6. Simulates the JSON evaluation payload that gets transmitted to Google Cloud in Step 4.
